單一因子跟「未來5日報酬率」的 Pearson 相關係數，Apps Script 現場算，秒級出結果， 適合快速看某個因子最近有沒有還在有效。跟下面「因子回歸模型」的差別：這裡一次只看一個因子， 不用 BigQuery；因子回歸模型是同時考慮多個因子（LASSO 迴歸），還會挑出最佳組合、記錄歷史。

因子相關性掃描

以大表所有欄位為基礎，用 BigQuery ML 找出目前最能預測「後續1個月報酬率」跟 「相對大盤抗跌力」的因子組合（多因子 LASSO 迴歸，比左邊的單因子相關性更深入）， 結果記錄在下面，可以觀察因子有效性有沒有隨市場漂移。這是選用的進階功能， 需要你自己有一個 GCP 專案（見 README「因子回歸模型」章節的設定步驟）， 這裡的沙盒環境不能代為設定。套用某一版之後，最新戰報會多顯示一組「因子模型預測分數」 供對照，但不會改變 Armor_Score 本身的選股邏輯。
三個模式選一個之後，最新戰報／個股分析／回測研究／因子相關性掃描都會跟著改變資料來源 （native 模式維持讀 Drive 月份檔案，另外兩個都會改成查 BigQuery）：
external（即時讀取）：不用先匯入，執行任何一項查詢前都會自動把 BigQuery 外部資料表 重新指向歷史資料夾裡「目前所有」CSV 檔案，Apps Script 完全不會讀取檔案內容。 缺點：每次查詢都要即時讀 Drive，比較慢；且用「欄位順序」對應 schema， 如果 Drive 上 CSV 的實際欄位順序跟系統不一樣，資料會整個對錯欄卻不會報錯。
materialized（推薦）：一樣不用匯入，但改用「欄位名稱」對應（BigQuery 自動辨識 CSV 標題列文字當欄名，不管來源檔案欄位順序如何都不影響，對不上名字會直接報錯，不會靜默算錯）。 執行查詢前只有「超過設定的重新整理間隔（預設 6 小時）沒整理過」才會真的重新整理一次 （複製資料進 BigQuery 原生表），其餘時候直接沿用，速度接近 native 模式；每天排程抓完 當天資料後也會自動強制重新整理一次，正常情況下完全不用手動按任何按鈕。
